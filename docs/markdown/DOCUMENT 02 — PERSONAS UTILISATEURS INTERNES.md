# **02.1 --- Introduction**

Les personas permettent de définir précisément **qui utilise TFLE**,
pourquoi ils l\'utilisent et quelles sont leurs attentes.

Contrairement à un SaaS commercial classique, TFLE ne cible pas des
milliers d\'utilisateurs externes.

Son objectif est d\'être un outil interne extrêmement efficace pour une
équipe réduite.

La conception doit donc privilégier :

- la rapidité d\'utilisation ;

- la clarté des informations ;

- l\'aide à la décision ;

- la réduction des tâches répétitives.

# **PERSONA 01 --- Fondateur TableFlash**

## **Identité**

**Nom fictif :** Julien\
**Fonction :** Fondateur / CEO TableFlash\
**Utilisation :** Quotidienne

# **Profil**

Le fondateur possède une vision globale de l\'entreprise.

Il doit comprendre :

- où se trouvent les opportunités ;

- quels restaurants contacter ;

- quelles zones sont prioritaires ;

- quelles actions génèrent des clients.

Il utilise TFLE comme un **centre de commandement commercial**.

# **Objectifs**

## **Objectif principal**

Développer rapidement le portefeuille clients TableFlash.

## **Objectifs secondaires**

- Identifier les meilleures zones géographiques.

- Comprendre le marché.

- Optimiser la stratégie commerciale.

- Mesurer la performance.

# **Problèmes actuels**

Avant TFLE :

- recherche manuelle des restaurants ;

- manque de visibilité ;

- difficulté à prioriser ;

- temps perdu sur des prospects peu pertinents.

# **Besoins fonctionnels**

Le fondateur veut voir :

### **Dashboard stratégique**

Exemple :

Restaurants analysés :

12 540

Prospects prioritaires :

1 420

Contacts réalisés :

320

Essais gratuits :

48

Clients :

15

### **Carte du marché**

Visualisation :

- zones couvertes ;

- zones à fort potentiel ;

- densité de restaurants.

### **Intelligence commerciale**

Il veut comprendre :

- pourquoi un restaurant est intéressant ;

- quels arguments utiliser ;

- quels profils convertissent.

# **Actions fréquentes**

- Consulter les meilleurs prospects.

- Modifier les règles de scoring.

- Analyser les performances.

- Définir les priorités commerciales.

# **Critères de réussite**

Le système est réussi si le fondateur peut répondre rapidement à :

> \"Quels sont les 20 restaurants que je dois contacter cette semaine et
> pourquoi ?\"

# **PERSONA 02 --- Commercial TableFlash**

## **Identité**

**Nom fictif :** Thomas\
**Fonction :** Commercial terrain / téléprospection\
**Utilisation :** Quotidienne

# **Profil**

Le commercial n\'a pas besoin de comprendre la technologie.

Il doit disposer d\'informations simples et exploitables.

Son rôle :

Transformer une opportunité en client.

# **Objectifs**

## **Objectif principal**

Contacter les bons restaurants avec le bon argument.

## **Objectifs secondaires**

- Organiser ses relances.

- Préparer ses appels.

- Suivre les essais gratuits.

- Mettre à jour les informations.

# **Problèmes actuels**

Sans TFLE :

- appels sans préparation ;

- manque d\'informations ;

- difficulté à se souvenir des échanges ;

- relances oubliées.

# **Besoins fonctionnels**

Le commercial doit avoir une fiche claire.

Exemple :

Restaurant :

La Petite Brasserie

Score :

92/100

Pourquoi intéressant :

✓ Restaurant indépendant

✓ Menu PDF uniquement

✓ Aucun QR code détecté

✓ Forte fréquentation

Argument conseillé :

\"Vous pourriez remplacer votre carte papier

par un menu interactif accessible par QR code.\"

# **Actions fréquentes**

- Ouvrir une fiche restaurant.

- Lire le résumé IA.

- Ajouter une note.

- Modifier le statut.

- Programmer une relance.

# **Critères de réussite**

Le commercial doit pouvoir préparer un contact en moins de 2 minutes.

# **02.5 --- Principes UX issus des personas**

La conception de TFLE devra respecter :

## **1. L\'information importante doit être visible immédiatement**

Le score et la raison du score doivent apparaître sans ouvrir plusieurs
pages.

## **2. L\'utilisateur doit toujours savoir quoi faire ensuite**

Exemple :

Action recommandée :

Appeler ce restaurant aujourd\'hui

## **3. L\'IA doit expliquer ses décisions**

Pas seulement :

Score : 90

Mais :

Score : 90

Pourquoi :

\- Pas de QR code

\- Menu PDF

\- Site ancien

\- Restaurant indépendant

# **02.6 --- Conclusion**

Les personas définissent une règle fondamentale :

> TFLE ne doit pas être un outil de données. Il doit être un outil de
> décision.

Chaque écran, chaque fonctionnalité et chaque automatisation devra
répondre à une question simple :

**\"Est-ce que cela aide TableFlash à trouver et convertir plus
rapidement les bons restaurants ?\"**
